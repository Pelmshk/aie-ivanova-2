# Итоговый проект по курсу «Инженерия Искусственного Интеллекта»

В этой папке находится итоговый мини-проект по курсу.  
Проект должен демонстрировать применение методов и инструментов инженерии ИИ: работу с данными, модели, пайплайны, сервис, эксперименты и (по возможности) воспроизводимость.

## 1. Паспорт проекта

- **Название проекта:** Recipe Search API — Сервис поиска рецептов по ингредиентам
- **Автор:** Иванова Полина Александровна
- **Группа:** БИСО-01-23
- **Контакт:** po_iva_nova@bk.ru

- **Краткое описание (2-4 предложения):**  
  Проект посвящен построению сервиса для поиска рецептов на основе списка ингредиентов, указанных пользователем.
  Используется открытый датасет Recipes Dataset (Recipes Dataset for NLP): https://www.kaggle.com/datasets/thedevastator/better-recipes-for-a-better-life/data
  В качестве поискового движка используется алгоритм BM25, который показал наилучшие результаты по метрике NDCG@10 в ходе экспериментов в сравнении с TF-IDF и embedding-моделями.
  Результат - REST API, который по списку ингредиентов возвращает список рекомендованных рецептов по совпадению с запрошенным списком.

## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` – зависимости проекта (библиотеки Python, необходимые для запуска).
- `report.md` – отчёт по проекту (постановка задачи, данные, эксперименты, результаты).
- `self-checklist.md` – чеклист самопроверки проекта перед сдачей.
- `notebooks/` – экспериментальные ноутбуки:
  - EDA, прототипы моделей, отдельные эксперименты.
- `src/` – основной код проекта:
  - модули для работы с данными;
  - обучение моделей;
  - запуск сервиса/скриптов.
- `data/` – содержит обработанные данные для работы сервиса (сырые данные исключены):
- `configs/` – конфигурационные файлы:
  - `settings.py` – централизованные настройки приложения, читаемые из переменных окружения.
  - `.env.example` – шаблон переменных окружения (порты, пути к артефактам, уровни логирования).
- `tests/` – тесты (юнит-тесты, простые проверки).
- `artifacts/` – сохранённые модели, отчёты, результаты экспериментов.
- `Dockerfile` – файл для контейнеризации и локального развёртывания сервиса.

## 3. Требования и установка

### 3.1. Требования

- `Python` >= 3.10`
- `Docker` (для запуска контейнера)
- `Git`

### 3.2. Установка окружения

Для локального запуска без Docker:
```bash

cd project

# Создать виртуальное окружение
python -m venv .venv
source .venv/bin/activate  # Для Windows: .venv\Scripts\activate

# Установить зависимости
pip install -r requirements.txt
```

## 4. Как запустить проект

### 4.1. Запуск через Docker

1. Сборка образа:

```bash
cd project
docker build -t recipe-recommender:v2 .
```

2. Запуск контейнера

```bash
docker run -p 8000:8000 recipe-recommender:v2
```

### 4.2. Локальный запуск

```bash
cd project
uvicorn src.service.main:app --reload --host 0.0.0.0 --port 8000
```

- Сервис будет доступен по адресу: http://localhost:8000.
- Эндпоинты:
  - / – Корневой эндпоинт. Возвращает информацию о сервисе и доступных методах.
  - /docs – Документация API (Swagger UI).
  - /health – Проверяет работоспособность сервиса и загрузку модели.
  - /metrics – Возвращает базовые метрики сервиса.
  - /search (POST) – Возвращает рецепты, отсортированные по релевантности запросу.

Все эндпоинты также доступны через автоматическую документацию (http://localhost:8000/docs).

## 6. Тесты

Проект содержит набор автоматизированных тестов для проверки стабильности API и корректности работы модели поиска.
Используются следующие виды тестов:
- Smoke-тесты (tests/test_health.py): Проверяют базовую доступность сервиса, корректность ответов эндпоинтов /health и /metrics, а также наличие документации.
- Integration-тесты (tests/test_search.py): Проверяют логику поиска по ингредиентам, структуру ответа JSON, обработку пустых запросов и валидацию входных параметров (например, ограничение на top_k).


Запуск тестов:

```bash
cd project
pip install pytest httpx
pytest tests/ -v
```

## 8. Ограничения и дальнейшая работа

В текущей версии проекта реализован поиск на основе алгоритма BM25, который обеспечивает высокую скорость работы и точное лексическое совпадение, но имеет следующие ограничения:
- Отсутсвует анализ семантики (синонимы, описательния)
- Упрощенное ранжирование (без учёта качества рецепта или удобства для пользователя)
- Очистка ингредиентов реализована через регулярные выражения и может работать некорректно на сложных или нестандартных формулировках из датасета.


В дальнейшем можно добавить:

- Внедрение векторных эмбеддингов в дополнение к BM25 для поддержки семантического поиска и работы с синонимами.
- Учет дополнительных данных при расчете финального скоринга выдачи.
- Возможность фильтровать результаты по типу кухни, диете или калорийности.
- Простой веб-интерфейс для удобного ввода ингредиентов пользователем и отображения карточек рецептов.
